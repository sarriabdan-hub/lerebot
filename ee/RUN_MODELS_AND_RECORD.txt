--- WHAT WAS BROKEN -> HOW IT WAS FIXED (all Thor) ------------------

1. `pip install ... decord` FAILED (no aarch64 wheel).
   decord is a TRAINING-ONLY video backend (configuration_groot.py),
   never imported at inference. On Thor install ONLY:
       pip install dm-tree timm ninja      (diffusers already present)
   OMIT decord. pi0.5 needs no extra deps at all.

2. GR00T load -> "FlashAttention2 ... doesn't seem to be installed".
   flash_attn has no aarch64 wheel; Eagle backbone forces
   flash_attention_2 in THREE spots in
     lerobot/.../groot/eagle2_hg_model/modeling_eagle2_5_vl.py
   PATCHED all three to fall back to sdpa when flash_attn is absent
   (guard before super().__init__; vision tower line; Qwen assert),
   then cleared the eagle caches. GR00T now loads clean. Re-apply if
   lerobot is re-cloned. Full details in section 1.2 above.

3. Motor bus ConnectionError on id_=4 after a prior core-dump.
   -> power-cycle the arm + sudo chmod 666 /dev/ttyACM0. Fixed.

4. vla_server appeared to HANG ~13 min after model load (looked frozen
   at the placo self-collision warning — that is just stdout buffering
   behind `tee`; the python prints after it are block-buffered).
   Real cause: RealSense cam_side was on USB 2.1 -> pipeline.start()
   blocked forever in camera warmup.

5. RealSense USB saga (the big time sink):
   - The USB-A extension cable was FAULTY -> pinned the D435i to USB 2.1.
   - Thor's USB-C port is a UCSI/CCG dual-role port (tegra-xudc), boots
     in DEVICE mode. Writing 'host' to
       /sys/class/usb_role/usb2-0-role-switch/role
     flips the data mux but does NOT source VBUS, so the camera never
     enumerates on that USB-C port (zero kernel events on replug).
   - FIX: RealSense on a USB-A 3.0 port with a good USB3 data cable
     (new USB-A<->USB-C). Now USB 3.2, depth streams, 93% coverage @
     0.30-1.01 m. Sample frames: ee/rs_color.png, ee/rs_depth.png.
   - cam_top/cam_wrist are hardcoded by-path (4.2.2->video6,
     4.2.4->video8) — DO NOT MOVE THEM. Baseline: ee/camera_port_baseline.txt

6. Added a fast pre-flight to ee/vla_server.py so this never wastes
   time again:
     - preflight_realsense(): ~1s check that cam_side is present at USB3
       BEFORE the multi-minute model load; exits with a clear message if
       on USB2/missing.
     - connect_robot_with_timeout(): hard 60s cap on robot+camera connect.
     New flags: --skip-preflight, --camera-timeout <s> (default 60).

     ids=[1..6] ... [TxRxResult] Port is in use!
   => two things drive the Feetech serial bus (/dev/ttyACM0) at once.
   Findings:
     - /observe (vla_server.py ~L978) -> observe_images() reads the motor
       bus; the home/execute loops also call follower.get_observation()
       for the live overlay (~L818/L826/L839).
     - The GUI polls /observe continuously -> collides with the run.
     - Even a lock-holding /home failed, so a background reader is

       stray /observe poller / async-chunk producer thread).
   Likely fix: route EVERY follower.get_observation()/motor read through
   ROBOT_LOCK (or a dedicated motor lock), and make /observe serve ONLY

   Workaround until fixed: do NOT open any GUI; ensure nothing polls
